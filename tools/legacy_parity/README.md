# Legacy FSPS parity check

Compares this fork with legacy FSPS (Conroy's Fortran, built from source) on identical data, so
that differences reflect code, not inputs. The fork's own regression references are generated by
the fork and only detect change; this check, together with `tests/test_physics_oracles.f90`, is
what anchors the fork to independent results.

Both scripts need:

- `LEGACY_SRC`: a clean legacy `src/` directory (`git -C fsps archive HEAD src | tar -x`) whose
  isochrone layout matches the fork's data tree. The fork ships the older MIST layout
  (`isoc_z*.dat`); upstream master has moved to `isoc_feh_*_afe_*`, so use a legacy checkout
  from before that change (the numbers below are from upstream 82a8735).
- `LEGACY_SPS_HOME`: a legacy-layout data tree (`SPECTRA/`, `ISOCHRONES/`, ...) whose files are
  byte-identical to the data the fork reads. Upstream FSPS at 82a8735 is one: its `SPECTRA/`,
  `ISOCHRONES/`, `dust/` and `data/` are byte-identical to `data/spectra/`, `data/isochrones/`,
  `data/dust/` and `data/` of `elijahmathews/fsps` at `fsps-final`, the tree the `opensps-data`
  release was converted from, and its `nebular/` differs only in the six line tables below.
- `DATA_HOME` (default `OPENSPS_DATA_HOME`): the fork's data root, e.g. the unpacked
  `opensps-data` release (`tools/fetch_data.py`). `test_data_parity LEGACY_ROOT STANDARD_ROOT`
  (built with the tests) checks that it matches a legacy tree bit for bit.
- gfortran, Python 3 with NumPy, and the fork configured in `build/` (or `BUILD=<dir>`, relative
  to the repository root).

Legacy FSPS is built in double precision (`SP = KIND(1.d0)` in `sps_vars.f90`), so the two codes
agree to about 1e-6 wherever they compute the same thing.

## Parity matrix

```
tools/legacy_parity/run_matrix.sh LEGACY_SRC LEGACY_SPS_HOME [OUTDIR]
```

Runs every case of `tests/data/param_cases.psv` (IMFs, SFHs, all dust types, dust emission,
nebular emission, IGM, AGN, smoothing, the Padova + BaSeL, MIST + C3K, THEMIS and BPASS
libraries) through both codes and compares them case by case with `compare_matrix.py`, which
writes `OUTDIR/report.txt` and exits non-zero if a tolerance is exceeded. It takes about 3 min
on 4 cores (`JOBS`, default 4).

To compare code rather than constants, legacy is built with two patches (`patches/`):

- `constants.sed`: the fork's constants (IAU 2015 / CODATA 2018, and the exact 1/(4 pi sigma)
  in place of legacy's `gsig4pi = 1/4.13e10`, which makes every main-library spectrum 1.77% too
  bright); cconroy20/fsps#83.
- `agn_dust.sed`: upstream d9a387a, which scales the AGN torus attenuation by `dust2`
  (cconroy20/fsps#81).

The data tree is the legacy one with the corrected nebular line tables that the fork's data
holds, taken from `LEGACY_NEBULAR` (e.g. `data/nebular/` of `elijahmathews/fsps` at
`fsps-final`): legacy's own `ZAU_{ND,WD}_{mist,pdva,prsc}.lines` carry wrong metallicity and age
labels. They are upstream fc7db5a's tables, with the header and wavelength row of the three `WD`
tables made consistent with their 166 lines (`elijahmathews/fsps` d5ebb2d; upstream's `WD` headers
still list 128).

### Results

Every case passes at every age. Where no intentional difference is involved:

| Quantity | Measured (max over cases) | Tolerance |
|---|---|---|
| log M, log L_bol | 6e-7 dex | 2e-6 dex |
| Spectrum per pixel, 912 A - 2.5 um | 2.8e-6 | 5e-6 |
| Spectral indices | 1.5e-5 | 1e-4 |
| Emission lines | 1.6e-7 | 1e-6 |
| Magnitudes, bands below / above 2.5 um | 0.0012 / 0.0047 mag (filter clamp, below) | 0.003 / 0.01 mag |

Cases that exercise an intentional difference get a wider tolerance, labelled in the report
with the difference responsible (`OVERRIDES` in `compare_matrix.py`).

## Intentional differences from legacy FSPS

Each was traced to its source; where the fork differs it is because legacy is grid-dependent,
loses energy, or uses rounded constants.

| Difference | Effect against legacy | Matrix cases |
|---|---|---|
| Constants: IAU 2015 / CODATA 2018 and exact 1/(4 pi sigma) (#83) | Legacy spectra 1.77% brighter (`gsig4pi`); AGB dust and WR winds shift | Patched out |
| IMF weights and remnant masses from exact integrals (lognormal parts: erf for wide bins, 5-point Gauss-Legendre for bins narrower than 0.1 in the erf argument, where the erf difference would cancel) | Legacy's Romberg integration (1e-7 per bin) shifts Chabrier and van Dokkum by up to 1.4e-6 in spectra, 1e-6 dex in mass; other IMFs identical | Chabrier, van Dokkum |
| Dust self-absorption summed analytically (#82) | Legacy's iteration loses up to 0.25% of L_bol: 1.4% of the dust emission for a power-law curve (dust_type 0, the default); about 0.1% of the AGB-dust IR | dust_type 0 with dust emission |
| Filter transmission clamped at 0 before normalization | Legacy normalizes with the negative values its linear edge extrapolation produces: LSST u +0.0008, LSST y +0.0005, Bessell M +0.004 mag | All |
| Calzetti R_V = 4.05 exactly | Legacy's 4.0455: 3e-4 in attenuated spectra | dust_type 2, 4 |
| Reddy curve constant blueward of exactly 1500 A | Legacy holds the value of the pixel below 1500 A (grid-dependent): 2e-3 below 1500 A | dust_type 6 |
| CCM UV/optical junction matched at exactly x = 3.3 | Legacy matches at the nearest pixel (grid-dependent): 2e-5 at 3000 A | dust_type 1 |
| Velocity smoothing kernel | Exact across the MILES grid-spacing jumps, where legacy's is wrong: up to 1.3% at those pixels for sigma = 150 km/s | smooth_velocity |
| LSF smoothing (`smooth_lsf`) always a velocity convolution by the context's LSF table | Legacy passes a placeholder sigma of 99 to `smoothspec`, which with `smooth_velocity = 0` convolves with a 99 A Gaussian and ignores the LSF table (the table is read from `lsf.dat` there; here it is supplied through the context) | `smooth_lsf` with `smooth_velocity = 0` |
| Remnant turn-off from the native isochrone, not appended blue stragglers | Legacy loses 2-5% of M_* with sbss > 0 | sbss > 0 |
| Blue-straggler ZAMS from main-sequence arrivals | On MIST, legacy places stragglers among M dwarfs (no light); the fork on the upper MS (+0.011 dex L_bol at 10 Gyr for sbss = 2) | sbss > 0 |
| BPASS L_bol from the integral of its spectra | Legacy reports log L = 0 at every age | BPASS |
| AGN template floor 1e-30 | Legacy uses its tiny floor: differs only far in the EUV | - |

The matrix also checks the parity decisions that went the other way, where the fork now does
what legacy does: the corner order for partially covered spectral-library cells, interpolation
of index band edges as a ratio, the 1e-70 floor of the library metallicity interpolation,
nebular line tables, and the fork bugs fixed on the way (delayed-tau first moment, single-age
CSP mass, ignored IMF limits, Padova horizontal-branch detection, NaN indices on coarse grids).

## Quick check

```
tools/legacy_parity/run.sh LEGACY_SRC LEGACY_SPS_HOME [OUTDIR]
```

Builds legacy with only the `gsig4pi` correction (legacy's other constants unchanged) and the
small driver `ssp_dump.f90`, dumps a Chabrier, solar, MIST + MILES SSP grid with
`add_agb_dust_model = 0` from both codes, and runs `compare_legacy.py`. It takes about 20 s.
The residuals are those of the constants: 3.6e-5 median and 2.9e-4 at the 99th percentile for
log t >= 7, and up to 7e-3 per pixel for log t < 7 (Wolf-Rayet winds), all well inside the
tolerances in `compare_legacy.py`.

## [alpha/Fe] against legacy FSPS v4

`afe/run_afe.sh LEGACY_V4_SRC LEGACY_V4_SPS_HOME AFE_DATA_ROOT [OUTDIR]` compares the SSP of legacy FSPS v4
(cconroy20/fsps master, built with `-DAFE_FLAG=1`: MIST v2.5 + C3K_LR, 13 Z x 5 [alpha/Fe]) with this fork's, at the
five [alpha/Fe] nodes of one metallicity (`ZMET`, default 11 = solar; `EVTYPE` selects one evolutionary phase;
`AGB_DUST=0` turns the AGB dust off in both). Legacy has no [alpha/Fe] interpolation, so only the nodes can be compared;
the interpolation (bilinear in log Z and [alpha/Fe]) is checked by `tests/test_afe_library.f90` and the oracles of
`test_csp_batch`. The legacy copy is built in `OUTDIR` with `patches/constants.sed` and the label fix below.

Result (Chabrier, solar; all ages 0.1 Myr - 20 Gyr, 100 A - 1 mm), with the fork's options set to legacy v4's defaults
(`use_lw_tpagb = 0`, `logt_wmb_hot = 10`):

| | Maximum difference |
|---|---|
| Mass, L_bol | 2e-6 (IMF integrals) |
| Spectrum, AGB dust off | 2.5e-6 of the age's peak flux per pixel, every node, Z = 2 and 11 |
| Spectrum, AGB dust on | 2.6e-4 of the peak (1e-3 of the local flux), all of it beyond 1 um in the AGB phases |

Differences found, and where they went:

| Difference | Effect against legacy v4 | Status |
|---|---|---|
| Main-library corner validity: legacy tests the 5000 A flux against `tiny30` = 1e-30 and stores the library in single precision, where the converted libraries' 1e-70 filler is zero; the fork tested against `tiny(1.0_wp)` | C3K_LR has fillers at the hot, low-gravity edge: stars hotter than the grid averaged with the filler instead of snapping to the real corner (spectra of log t < 6.6 down 15-30%, post-AGB UV down 70%) | Fixed (the fork now uses 1e-30, as its HIP kernels already did) |
| `isoc_type == 'mist'` tests (WR wind radius, horizontal-branch tags) did not cover `mist_afe` | WR stars' spectra 14% low | Fixed (`isoc_is_mist`) |
| `use_lw_tpagb` (legacy v4 default 0): O-rich TP-AGB stars from the main library, not Lancon & Mouhcine (2002) | TP-AGB optical 8-15% low, UV zero (the LM02 spectra have none); up to 0.3% of the total optical | New option `use_lw_tpagb`, default 1 (what the fork did until now and what legacy at 82a8735 does); legacy v4 parity needs 0 |
| AGB dust threshold: legacy skips stars with tau1 <= tiny_number (1e-70); the fork's was 2e-308 | Hot massive E-AGB-tagged stars of MIST (tau ~ 1e-60) got the extrapolated screen of a cool star: one log t = 6.65 isochrone off by 6% in the UV, 16% in the IR | Fixed (`AGB_TAU_FLOOR`) |
| **Legacy bug:** `sps_setup` reads the C3K [Fe/H] labels with `F4.2`, so "-2.25" becomes -2.2, "-1.75" -1.7, "-0.25" -0.2, "+0.25" +0.2 (every label that is not a multiple of 0.5) | Legacy's Z grid for the library is off by 0.05 dex at six of the 13 metallicities; its spectra there are blends with the neighbouring metallicity: up to 0.3-0.8% of the peak (3% locally in the UV) at Z index 2 and 8 | Not reproduced; the parity run patches legacy to `F5.2`. To be reported upstream |
| AGB dust: the circumstellar screen's smoothing beyond 3 um (`smoothspec`, sigma = 1e4 km/s) | Legacy's kernel is symmetric in pixel index, not in velocity, on a non-uniform grid (C3K_LR is); with `smoothspec_fast = 0`, which resamples, the 10 um - 1 mm residual drops from 1e-3 to 1e-4 but the 1-10 um one grows (4e-3); the fork's is the exact kernel | Same intentional difference as the velocity smoothing kernel above; the IR beyond 2.5 um is not gated |

The first four are bugs or missing options of the fork that the afe libraries exposed: the main-library corner test and
the AGB dust floor also apply to every other library, and the regression references are unchanged by them.
Not compared: the [alpha/Fe]-dependent nebular grids (legacy has none: its CLOUDY grids use [Fe/H] only), and CSPs.

## python-fsps

python-fsps is a fixed, unpatched legacy build, so it cannot be used for this check. As a smoke
test, fork/python-fsps spectra for log t >= 7.2 should sit at 0.9827 +- 0.001 (the gsig4pi
ratio), with mass and L_bol agreeing to 1e-3 dex.
